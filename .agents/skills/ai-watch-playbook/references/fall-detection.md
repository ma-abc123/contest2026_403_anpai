# 跌倒检测：算法参数、定标工作流、已知的坑

## 架构

`ai_watch_motion.c`：开机自启后台 pthread，独占 `/dev/lsm6dsl0`，
25ms 轮询（实际 ~15Hz，受驱动 22 次单字节读限制）；算法全在线程内，
快照（mutex）+ 事件队列给主循环；LVGL 线程零 I2C。

## 参数速查（最终值，演化见下）

| 域 | 参数 |
|---|---|
| 计步 | 迟滞：峰 >1150mg / 谷 <850mg；不应期 300ms；步长 0.7m |
| 活动 | 2s 窗 std：<30mg 静止 / >350mg 跑步 / 其余步行；同级 ~1s 防抖 |
| 冲击 | >2400mg 单点；或 <550mg 自由落体后 500ms 内 >2000mg 单点；或 >2000mg 两连点 |
| 确认 | 3s 观察窗（dev>200mg/mag>2000mg 顺延），末 1s 波动 <80mg 且均值 ~1g±150mg |
| 姿态 | 快速重力向量（冻结于冲击时刻）vs 当前重力夹角 ≥50° |
| 平落备用 | 有自由落体 + 落后静止 ≥4.5s（观测预算 10s）→ 也告警 |
| 冷却 | 拒绝后 8s；告警/取消后 60s |
| 告警 | 全屏 15s 倒计时；CANCEL 或 KEY2 取消；超时上报 FALL_EVENT |

事件码：1=确认未取消 / 2=已取消 / 3=测试触发（Test 按钮直进倒计时态）。
UI/上报文案统一"疑似跌倒"，不宣称医疗级。

## 定标工作流（先离线后上板）

1. 手表 Exercise 页 Record → 串口全量 CSV：`REC,t_ms,x,y,z,gx,gy,gz`
   （~15Hz；BLE 0x12 为 1/4 抽样视图，仅供手机存档）。
2. 采集场景：静止/走路/跑步/抬腕/受控倒伏（落地后保持静止 5s+）/磕桌/
   甩动。**文件名含 "fall" = 期望触发，不含 = 期望不触发**（脚本判分规则）。
3. `tools/fall_threshold_analysis.py <logs...>`：按 t_ms 归零自动分会话，
   **镜像固件同一条状态机**回灌，输出每组 |a| 统计、事件与 PASS/FAIL。
4. 调参用 CLI 参数（`--impact-hard/--impact-soft/--ff/--angle/--still-dev/
   --long-still/--window`）扫到全绿，再写回固件常量，实机回归。

## 三个用真数据换来的教训

1. **姿态基准必须用快速重力滤波（α=0.15，~1s 收敛）且初值用 mg 量纲**
   （0,0,1000）。慢滤波（α=0.01，τ≈6.7s）+ 初值 (0,0,1) 的组合在"开机
   几秒就倒"时会给出垃圾角度（实测 34° 拒掉一次真倒伏）。
   分析脚本与固件不同源（初值/规则不一致）会让离线结论失真——两者必须
   逐参数镜像。
2. **低采样率下自由落体门限不能用时长**：~15Hz 时短自由落体只采到 1 个
   样本，"≥60ms 持续"永不满足。改为单样本锁存 + 500ms 新鲜度窗口。
3. **静止门是防误报核心，不要绕过**：重砸后立刻拿起与磕桌在数据上
   不可区分，"impact followed by motion" 是正确拒绝。平落不转身（夹角
   仅 27°）靠"自由落体 + 长静止"备用路径覆盖，而非放宽角度门。
