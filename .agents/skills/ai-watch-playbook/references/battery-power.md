# 电池、充电与电量计（SF32LB52 黄山派）

## 硬件事实（wiki + 板级代码交叉确认）

| 项 | 值 |
|---|---|
| 电池接口 | GH-1.25mm 母座，**正向线序**，单芯锂电 |
| 模组 VBAT 输入 | 27 脚，3.7~4.7V（不接电池时常压供电推荐 3.8V） |
| 模组 VBATS | 62 脚，**电池电压检测输入**，内部接 GPADC |
| 充电 IC | **AW32001ECSR**，7-bit 地址 **0x49**，SCL/SDA = **PA10/PA11** |
| 充电能力 | 最大 500mA，出厂默认 450mA 恒流 |
| 模组电源阈值 | 开机 **3.58V** / 关机 **3.48V**（wiki 原文） |

### 跳线帽是硬前提

30p 排针必须短接，否则电池不参与供电：

- **5-6 脚**：VBAT_S ↔ VBAT
- **7-8 脚**：VSYS_S ↔ VSYS
- **11-12 脚**：VCC_3V3_S ↔ VCC_3V3

这三组是预留的功耗测量断点，出厂未必插跳线帽。**电池装上但不供电时先查这里。**

### 纯电池冷启动：要等约 10 秒，不是故障（2026-10-28 用户实测定论）

只插电池、不接 USB，**通电后不动，约 10 秒屏幕才亮**。此前多次报"单电池
开不了机"都是没等够。板上两个按键都不是复位键也不是电源键，**板子没有复位
键**，所以"长按所有键无效"是正常的，不能用来判断死活。

判断"真的没起来"的正确姿势：等满 15 秒再看，别按键。

`bsp_pinmux.c` 的 `BSP_PIN_Common()` 里 **PA38 = VSYS 使能**（低电平关轨），
原本配成 `PIN_PULLDOWN`，要等后面的 `BSP_PIN_LCD()` 才拉高；`PA26 = VCC_3V3`、
`PA30 = GS_3V3` 同理。插着 USB 时 VBUS 顶着看不出来，纯电池时这段窗口会让
电源轨塌一下。现已把 PA38 改成在 `BSP_PIN_Common()` 末尾立即
`BSP_GPIO_Set(38, 1, 1)`；PA26/PA30 未动（本来就在微秒级被拉高，改 PA30 会
提前打开传感器电源，属于未验证的时序变更）。

## ADC：读电池电压不需要写驱动

`sifli_ap.c` 已经在 bringup 里注册了 `/dev/adc0`，`sf32lb_adc.c` 用
`ctx->channel = ADC_CHAN_VBAT` 选通道。应用层只要：

```c
fd = open("/dev/adc0", O_RDONLY);
ioctl(fd, ANIOC_TRIGGER, 0);
read(fd, &sample, sizeof(sample));   /* struct adc_msg_s { ch, data } */
```

`sample.am_data` 已经是毫伏。**不需要新设备节点、不需要改内核。**

### 换算与量程

```
adc_mv = (value - 822) * 1068 / 1000        (ratio=1068, offset=822)
```

这组 ratio/offset 来自 `sf32lb_adc_calibrate()` 的**硬编码默认值**
（`vol10=1758 → 1000mV`、`vol25=3162 → 2500mV`）。真正的工厂校准走
`HAL_LCPU_CONFIG_get()`，但它在**单核板（黄山派）上会卡死在
`HAL_HPAON_WakeCore()`**，代码已改成跳过并打印
`ADC calibration data missing, use defaults`。因此绝对精度存疑，务必用万用表复核。

这组系数是**全通道共用**的（校准只算一次，与选哪个通道无关），所以换通道
不影响换算，只影响读到的原始值。

### 实测定论：电池在 ch7，分压 2:1（2026-10-28）

八通道扫描在"无电池 / 有电池"两次启动下对比，**只有 ch7 变化**：

| 通道 | 无电池 raw | 有电池 raw | 备注 |
|---|---|---|---|
| ch0/ch3 | 820 | 820 | 接地 |
| ch1/ch2/ch4 | 4004/3999/3999 | 3999/3996/3997 | ≈3.39V，固定轨 |
| **ch5**（原代码用的） | 3653 | 3654 | **插拔电池纹丝不动 → 不是电池** |
| ch6 | 824 | 824 | — |
| **ch7** | 2913 (2233mV) | 2736 (2044mV) | **唯一跟随电池** |

ch7 连读 5 次完全一致（2736×5，零抖动），三次启动 2711→2736→2747
**单调上升**——电池正在充电。这是"它就是真电池电压"最硬的证据。

**分压比 2:1 由反证确定**：插着电池拔掉 USB，手表继续运行 → 系统确实靠电池
在跑 → VBAT 必然 >3.5V；而 ch7 只读 2.04V → 只能是 1/2 分压。
（若按 1:1 解释会得到 2.0V 电池，那是过放保护状态，系统根本不可能运行。）

无电池时 ch7 浮到 2233mV（×2 = 4466mV），是 charger BAT 脚空载电压。

代码落点：`sf32lb_adc.h` 把 `ADC_CHAN_VBAT` 改成 `ADC_CHAN_7`；
`ai_watch_battery.c` 的 `BATTERY_DIVIDER_X100 = 200`。
实测输出 `BAT: adc=2057 mV raw, x2.00 -> 4114 mV, 93%`。

### 一次读阻塞 ~256ms（重要）

```c
for (i = 0; i < ADC_AVERAGE_COUNT; i++) {   /* 20 */
    ...
    HAL_Delay_us(10 * 1000);                 /* 每次 10ms */
}
```

`ADC_AVERAGE_COUNT = 20`，20 × 10ms = 200ms，加开销实测 **256ms**。

**所以 ADC 读绝不能放在 LVGL 主循环里**，否则每读一次 UI 冻 0.26 秒。
做法：独立低优先级线程（黄山派上 motion=80、light=90，电池线程用 **110**），
线程只更新变量，UI 由主循环读取后重绘。

## 坑：charger 的 I2C 在当前固件里是断的

`AW32001` 在 **PA10/PA11**，但：

- `sifli_ap.c:624` 把 **I2C2 外设**的 SCL/SDA 复用到 `PAD_PA40/PAD_PA39`
  （给 IMU + 光感用）
- 同一个外设不可能同时驱动两组引脚，于是 PA10/PA11 上的 I2C2 功能被放弃
- `bf0_i2c_cfg[]` 是**条件编译的紧凑数组**，`sifli_i2cbus_initialize(1)`
  取的是 `bf0_i2c_cfg[1] = BF0_I2C2_CFG (Instance = I2C2)`

**已实测确认（2026-10-28）**：在 `/dev/i2c1` 上扫 0x08~0x77，应答的是
`0x29`（LTR-303）、`0x6a`（LSM6DSL）和一个未识别的 `0x30`（首字节 0x61），
**`0x49` 无应答**。扫描本身是好的（两个已知器件都扫到了），所以这个静默
是真的没有器件，不是传输坏了。

**结论：当前固件下 `/dev/i2c*` 里没有任何一路通到 0x49。**
要读充电状态/改充电电流，需要另开 I2C3（`CONFIG_BSP_USING_I2C3`）并把它
复用到 PA10/PA11 —— 尚未验证 PA10/PA11 是否支持 I2C3 的 AF
（`bf0_pin_const.h` 里只有 `PA10_I2C_UART` 这一个笼统项）。

### 充电使能状态未知

`bsp_power.c` 只在 `is_deep_sleep` 分支里配置 AW32001（清 `POWER_ON_CFG(0x01)`
的 CEB bit3、关 `TIMER_WD(0x05)` 的看门狗）。**正常启动路径完全不碰它**，
所以充电是否使能取决于芯片 POR 默认值，目前未实测。

## AW32001 寄存器表（来自可用的开源实现）

| 地址 | 名称 |
|---|---|
| 0x00 | INPUT_SRC |
| 0x01 | POWER_ON_CFG（bit3 = CEB，清 0 = 使能充电） |
| 0x02 | CHG_CURRENT（8~456mA，步进 8mA） |
| 0x03 | TERM_CURRENT |
| 0x04 | CHG_VOLTAGE（默认 4200mV） |
| 0x05 | TIMER_WD（bit5-6 看门狗） |
| 0x06 | MAIN_CTRL |
| 0x07 | SYS_CTRL |
| 0x08 | SYS_STATUS（充电状态） |
| 0x09 | FAULT_STATUS |
| 0x0A | CHIP_ID |

充电状态枚举：0 = 未充电，1 = 预充，2 = 充电中，3 = 充满。

## 电池选型提醒

wiki 推荐 450~500mAh，默认充电电流 450mA。用户实配 **330mAh**，
按 450mA 充相当于 1.36C，偏大；正常应在 0.3~0.5C（**100~165mA**）。
若日后能打通 charger I2C，应把 `CHG_CURRENT` 调到 ~128mA（芯片默认值即可）。

## 首次接入的读数记录（2026-10-28，电池未接、纯 USB）

```
BAT: adc=3381 mV raw, x1.00 -> 3381 mV, 2% (256 ms)
BAT: settled raw=3382 mV vbat=3382 mV soc=2%
```

**这不是电池电压**，而且现在已经查清原因：3381mV 是 ch5 的读数，ch5 跟电池
毫无关系（插拔电池 3653/3654，一动不动）。当时"电池未接入却有 3.38V"的矛盾
纯粹测错了通道。真正的电池在 **ch7**，见上文实测定论。
