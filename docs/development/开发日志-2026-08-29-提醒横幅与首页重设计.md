## 1. 背景：实机联调暴露的三个问题

手机端（nRF Connect / 自研 App，MTU 253）向 Command(f4) 推送了两帧：

```
20:25:12  01 01 02 02 D4 D0 92 6A 09 E5 8F 96 E5 BF AB E9 80 92   提醒  id=2 flags=0x02 "取快递"
20:25:21  01 02 02 02 D4 D0 92 6A 09 E5 8F 96 E5 BF AB E9 80 92   通知  id=2 flags=0x02 "取快递"
```

手表串口日志显示两帧都已入队并解析（`command queued: 18 bytes`），
但屏幕上 Reminder 应用仍是空状态；同时用户报告首页两处文字重叠。

---

## 2. 问题 1（根因）：提醒列表恒为空

### 现象

`BLE: reminder[2] "取快递"` 已打印，Reminder 页面却显示 "No reminders"。

### 根因

`ai_watch_ble.c` 的 `ai_ble_cmd_reminder()` 把帧写入槽位后**从未维护
`g_reminders.count`**（memset 初始化后恒为 0），而 UI 刷新逻辑是：

```c
if (i < store->count && store->items[i].id != 0)  /* count==0 → 恒假 */
```

于是所有条目标签永远隐藏、永远显示空状态。数据其实在库里。

### 修复

新增 `ai_ble_recount()`：每次槽位变更后重新扫描 8 个槽统计非零 id 数
（防增防漏，比手动 ++/-- 稳健）。

### 顺带修复

- `struct ai_watch_reminder_s` 新增 `type` 字段（0x01 提醒 / 0x02 通知），
  此前两种帧走同一条日志，`01 02 ...`（通知）也被打成 "reminder"。
  现在日志区分 `notification[N]` / `reminder[N]`。
- 列表条目增加类型图标（🔔 提醒 / ✉ 通知）与本地化触发时间（HH:MM）。

---

## 3. 问题 2：推送到达无任何横幅/整页提醒

### 设计

- **数据通道**：`ai_ble_cmd_reminder()` 成功入库后向一个 4 深度的告警环
  `g_alerts[]` 压入一条（满时丢最旧、保最新）；CLEAR 命令清空环。
  主循环调用新增的 `ai_watch_ble_take_alert()` 逐条弹出。
  与既有 BLE→UI 约定一致：**BLE 上下文只入队，LVGL 只在主循环线程触碰**。
- **展示**：`ai_watch_main.c` 新增 Alert Banner 模块。横幅挂在
  `lv_layer_top()`（位于所有页面之上），宽 358 圆角卡片：
  第一行类型（`LV_SYMBOL_BELL Reminder` / `LV_SYMBOL_ENVELOPE Notification`，
  主题 accent 色），第二行标题（20px / CJK 16px）。
  点按立即关闭，6 秒无操作自动隐藏（一次性 lv_timer，新到达会重置）。
- 主循环在 `ai_watch_ble_process()` 之后 `while (take_alert) show()`，
  多条到达时依次刷新（后一条覆盖前一条的 6 秒计时）。
- 主题切换时 `ai_watch_alert_apply_theme()` 同步横幅配色。

## 4. 问题 3：首页重叠 → 重写

### 原布局的重叠根因

秒标签用 `lv_obj_align_to(seconds, time, OUT_RIGHT_MID)`、星期标签用
`lv_obj_align_to(dow, date, OUT_RIGHT_MID)` —— `align_to` 是**一次性坐标
快照**，不是约束；被参照标签文本宽度变化后不会跟随，冒号/星期便压到
相邻文字上。

### 新布局（390×450）

```
        AI Watch                (20px, y=26)
   Fri  2026/08/29              (16px, y=58, 星期与日期合并为单标签)

      08:41  27                 (48px + 28px accent, flex row 居中, 固定 10px 间距)
       🔔 2 unread              (有未读时显示, accent)

        BLE: ON                 (20px, bottom-64)
  Tap or swipe up for apps      (14px, bottom-24)
```

关键决策：

1. **星期与日期合并成单标签** —— 单个标签自身不可能重叠。
2. **秒数去掉前导冒号**（`:41` → `41`，accent 配色），与 `HH:MM`
   放进 `LV_FLEX_FLOW_ROW` 容器：任何一侧宽度变化都由 flex 重新流式
   排布，从机制上消除对 `align_to` 的依赖。
3. 所有元素改用 `lv_obj_align`（持久对齐，随尺寸重算）或固定坐标，
   删除全部 `align_to` 依赖。
4. 新增首页**未读指示**（🔔 N unread）：直接读提醒库统计未读数，
   不依赖 Reminder 页是否打开；数值变化才写标签。
5. `update_theme()` 不再用“第 0 个/最后一个子对象”索引猜标签，
   改为保存 `home_title_label` / `home_hint_label` 指针。

## 5. 中文标题字体（手机推“取快递”→ 屏幕显示“取□□”的问题）

手机推的标题是 UTF-8 中文，LVGL 内置 Montserrat 无 CJK 字形。
评估过内置 `lv_font_simsun_16_cjk`（1413 字形）：**缺“递/测/试/议/醒”
等常用字**（“取快递”显示“取□□”），不可用。

### 方案：自生成 CJK 字体（可复现）

- 字符集：**GB2312 一级字库 3755 汉字** + 全角标点 + ASCII（共 3782 字形），
  覆盖日常提醒/通知用字的 99.9%+。字符集存于
  `fonts/cjk_charset.txt`，验证脚本确认“取快递/开会提醒/测试通知”全覆盖。
- 转换：`fonts/gen_cjk_font.sh` 调 `lv_font_conv`（npm），
  源字体 Droid Sans Fallback，16px / 2bpp / 无压缩，生成
  `fonts/ai_watch_font_cjk_16.c`（v8/v9 双兼容）。
- 使用：标题类文本按内容选字体 —— `ai_watch_text_is_ascii()` 纯 ASCII
  用 Montserrat（保持与系统其它 UI 一致），含多字节则用 CJK 字体。
  覆盖点：横幅标题、Reminder 列表条目。
- 体积代价：固件 7.0MB → 7.8MB（flash 16MB 区域的 48.81%）；SRAM 占用
  不变（79.48%，字库数据在 XIP flash）。

# 第二轮（同日）：列表符号方框修复 + 全局右滑回主页

实机验证通过（首页布局、横幅、中文标题均正常）后，用户报告两个问题。

## 10. Reminder 列表标题前出现 6 个方框

### 根因

列表条目文本是 `LV_SYMBOL_EYE_OPEN + LV_SYMBOL_BELL + 时间 + 标题` 混合。
中文标题时整个标签切到 CJK 字体，而第一版 CJK 字体只含 ASCII + 汉字，
**没有 LVGL 的 FontAwesome 符号字形**（U+F06E/U+F0F3/U+F0E0…）。缺失
符号按 UTF-8 字节逐个画出占位方框：2 个符号 × 3 字节 = 6 个方框。

### 修复

`fonts/gen_cjk_font.sh` 在转换时追加第二个源字体——LVGL 自带的
`FontAwesome5-Solid+Brands+Regular.woff`，将 `lv_symbol_def.h` 中的
59 个 LV_SYMBOL 码点并入 `ai_watch_font_cjk_16`（仅 +4KB flash）。
注：`LV_SYMBOL_BULLET`(0x2022) 与 Brands 专有的 0xF8FF 在两个源字体中
均不存在且未使用，已从清单剔除。脚本注释同步更新。

## 11. 所有应用界面支持右滑回主页

### 需求

任意应用/设置页面右滑直接返回首页；**首页与蜂窝应用选择列表的手势
行为不得受影响**。

### 实现

- 新增 `ai_watch_go_home()`：离开动态应用页时先执行其 destroy 回调
  （与 `ai_watch_pop_page` 的清理路径一致），重置页面栈后以
  `LV_SCR_LOAD_ANIM_MOVE_RIGHT` 加载首页。
- `ai_watch_touch_update()` 手势分流重构：
  - 首页：保留原有"点按/上滑开应用列表"；
  - 蜂窝列表页：完全不动（六边形菜单的拖拽由其容器事件处理）；
  - 其余页面（Timer/Reminder/温湿度/心率/设置）：`dx > 50 且 |dx|>|dy|`
    触发回主页，竖向滑动（如 Reminder 列表滚动）不受影响。
- 原有的"手势须在 300ms 内完成"阈值保持一致，慢速拖动不会误触发；
  KEY2 的逐页返回保留，右滑是"直达首页"的快捷方式。

# 第三轮（同日）：列表图标移除、字体回退为纯 CJK

实机结果：右滑回主页 ✅；铃铛字形已能显示，但其后 "14:30" 五个字符
变成方框。

## 14. 五个方框的根因（**本节结论有误，已在第四轮 §18 纠正**）

把 FontAwesome 并入字体时，lv_font_conv 的 per-font `-r` 语义是
**替换而非合并**：第二个 `--font FontAwesome -r SYMS` 使第一字体
（Droid）的 `-r 0x20-0x7E` 失效，ASCII 数字/冒号被整体丢弃，且该
cmap 结构上没有逐字注释，构建期无法察觉。核验生成文件确认
U+0030/U+0031/U+003A 缺失 —— "14:30" 五字符即五个方框。

## 15. 按用户决定简化

- **列表条目图标全部移除**（👁 未读标记、🔔/✉ 类型图标）：未读状态
  仍以颜色区分（未读=正文色，已读=次级灰），首页保留 🔔 未读计数
  （Montserrat 标签，渲染正常）。条目文本只剩 `HH:MM 标题`。
- **字体回退为纯 Droid CJK**：`gen_cjk_font.sh` 删除第二字体分支，
  恢复与首轮完全一致的配方（3774 字形：ASCII 连续段 + GB2312 一级
  汉字 + 全角标点），并在脚本头部加注释**禁止**再向该字体追加第二
  `--font`（附原因），防止复发。
- 保留项（用户此前已确认正常）：横幅的类型行 `🔔 Reminder` /
  `✉ Notification` 用 Montserrat 渲染，不受影响；CJK 字体本身保留
  （否则中文标题又会变方框）。

# 第四轮（同日）：方框真正的根因 —— Droid Sans Fallback 没有拉丁字形

第三轮回退字体后，列表 "14:30" 五个字符**仍是方框**。第三轮日志中
"FA 替换 ASCII 段"的结论是误诊，本节纠正。

## 18. 真根因（解析字体 cmap 逐一验证）

1. **Droid Sans Fallback 本身没有基本拉丁字形**（数字/字母/多数
   ASCII 标点都没有）——它是纯 CJK 兜底字体。于是从第一轮起，
   `14:30` 就一直是方框；第一轮的"六个方框"实为 2 个缺失符号 +
   5 个时间字符。
2. lv_font_conv 的范围检查只要求请求范围内**至少一个字形存在**就
   静默通过（`collect_font_data.js` 的 is_empty 逻辑），缺字不报错。
3. 多字体时 `Ranger` 按"后写者胜"合并码位：字符集文件里混入的
   ASCII `,. ` 被后半 Droid 声明接管 → 无字形 → 被丢弃，形成
   0x2E 的空洞。

## 19. 修复（gen_cjk_font.sh 第四版）

- **ASCII 段改由 DejaVuSans.ttf 提供**（LVGL 自带，
  `-r 0x20-0x7E`），CJK 段仍由 Droid 提供（`--symbols`）。两字体
  按码位合并，无重叠 —— 这是 lv_font_conv 的标准多字体用法。
- `cjk_charset.txt` 过滤掉全部 ASCII 码位（避免被 Droid 接管），
  3779 个非 ASCII 字形。
- 脚本头部注释改写：记录 Droid 无拉丁字形的事实、"范围非空即通过"
  的静默失败模式，以及**重新生成后必须校验**（脚本内校验 ASCII
  0x20-0x7E 全覆盖 + 取/递在位）。
- 校验结果：ASCII 0x20-0x7E 全覆盖，U+53D6/U+9012 均在位。

# 第五轮（同日）：提醒生命周期 —— 已读/删除/清除

第四轮实机验证通过（方框消失 ✅）。用户指出：提醒没有已读选项，
会一直存在。应用版本 → `4.3.0`。

## 22. 设计

| 操作 | 行为 |
|---|---|
| **点按条目** | 已读 ↔ 未读 切换（未读=正文色，已读=次级灰；误触可再点回来） |
| **长按条目** | 删除该条提醒 |
| **Clear all 按钮** | 清空全部（等价手机端 CLEAR 命令），位于 Back 左右分列 |

首页的 🔔 N unread 直接轮询提醒库，标记已读后未读计数自动消失。

## 23. 实现

- `ai_watch_ble.c/h` 新增三个主循环线程接口（与解析器同线程，无锁）：
  `ai_watch_reminder_set_read(slot, read)`（翻转 READ 标志位）、
  `ai_watch_reminder_delete(slot)`（槽位清零 + 重计数）、
  `ai_watch_reminders_clear()`（全清）。三者均置 `pending` 触发
  Reminder 页 500ms 刷新与首页未读数更新。
- Reminder 列表条目标签开启 `LV_OBJ_FLAG_CLICKABLE` +
  `lv_obj_set_ext_click_area(8)`（16px 行高的触控容差），
  `LV_EVENT_CLICKED` → 切换已读，`LV_EVENT_LONG_PRESSED` → 删除。
- 刷新条件由 `i < store->count && id != 0` 改为仅 `id != 0`：
  删除会产生空洞槽位，原 count 前置判断会把空洞之后的条目隐藏。
- 未读状态协议位（flags bit0）与手机端一致，手机再次推送同 id 帧
  仍可覆盖状态。
