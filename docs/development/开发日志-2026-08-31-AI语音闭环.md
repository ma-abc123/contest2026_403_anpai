## 2. 协议扩展（ai_watch_ble.h）

f3 DataUpload 新增：

| sensor_type | 名称 | payload |
|---|---|---|
| 0x10 | AI_TRIGGER | [source(1)][ctx(N)]；0x01=AI 页按钮（无 ctx）、0x02=心率页（ctx=[hr u16][spo2 u16] LE，0=未知） |
| 0x04 | AI_TEXT | 复用命令帧：title=AI 回复 UTF-8 ≤224B（帧头 9B，需 MTU≥247），id=请求 id |
| 0x05 | AI_TIMER | timestamp 字段=时长秒（1..86400），落地为本地倒计时 |

设计约束：AI 回复的展示文案截断按 UTF-8 边界处理（回退续字节 0x80-0xBF，再判前导字节），避免切出乱码；`AI_WATCH_BLE_CMD_MAX` 240→适配 233B 帧。

## 3. AI 应用页（4.7.0）

- Start 按钮（mic 图标）→ `ai_watch_ble_send_ai_trigger()` → 状态 "Listening on phone..."，60s 超时回退
- 结果区：AI_TEXT pending 渲染，CJK 字体
- **倒计时独立运行**：`ai_watch_ai_countdown_poll()` 在主循环消费 AI_TIMER 请求，`CLOCK_MONOTONIC` 绝对到期，不依赖 AI 页是否打开；到期走条幅（"Timer done"）
- 应用注册表重排：AI 居中心位（index 0），Settings 仍保持 index==3（`ai_watch_open_app` 特判不动）

## 4. 心率页 I2C 卡顿——三轮根因链（4.7.1→4.7.3）

现象：进心率页卡顿甚至卡死在应用选择页。

| 版本 | 根因 | 修复 |
|---|---|---|
| 4.7.1 | SiFli HAL I2C 对不在线设备一次探测阻塞 1-2s（`I2C_TIMEOUT_ADDR/BUSY` 均 1000ms），在 LVGL 线程内执行 | 探测移入 pthread（4.7.2） |
| 4.7.2 | 探测线程持 I2C 驱动锁期间，LVGL 线程的 open()/传输撞锁冻结 | verdict PENDING 期间 LVGL 线程**零 I2C 接触**；首探前 300ms 切片延迟；absent 后 5s 退避（4.7.3） |

沉淀为模式：**传感器后台线程 + PENDING/OK/ABSENT 判定 + 主循环只读快照**。后续 M4 运动服务直接复用。

## 5. CCC 订阅模式兼容（4.7.4）

日志 `ai-watch-20260831-143116.log` 定位：手机端 CCC 写 **0x0002（Indication）**，而 f1/f3 只声明 Notify → `bt_gatt_notify` 报 "Device is not subscribed"，应用层拿到 -EINVAL/-22，AI 触发发不出去。

修复（vendor/sifli/chips/sf32lb52/sf32lb52_ble_bridge.c）：

- f1/f3 特征声明加 `BT_GATT_CHRC_INDICATE`
- 记录各特征 CCC 值，`ai_watch_ble_bsp_notify()` 按值分派：0x0002 走 `bt_gatt_indicate`（静态 params + pending 标志去重，-EAGAIN 丢新样本），否则 notify
- 断连回调清 CCC 缓存与 pending

## 6. 提醒到点条幅（4.7.5）

原行为只在收到命令时弹条幅。新增 `ai_ble_check_due()`（主循环 drain 命令后调用）：TimeSync 已同步前提下扫描提醒表，`id!=0 && type==REMINDER && !due_alerted && now>=timestamp` → 置位 + 弹同款条幅。每条一次；手机重发同 id 重新武装（`due_alerted` 字段按命令类型/时间戳复位）。
