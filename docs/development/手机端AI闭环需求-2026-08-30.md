# AI Watch 手机端迭代需求:语音/AI 闭环(v2)

> 用途:本文档是给手机端开发(AI 或人)的完整需求/提示词,可直接整篇粘贴。
> 基线:手机端 App v1 已按《AI Watch 手机端配套应用开发规范》实现(扫描/重连/TimeSync/提醒/DataUpload 仪表盘)。
> 手表端固件 4.7.0 已实现本文全部手表侧行为,协议以下述为准,勿再改动已有 UUID 与帧格式。

---

## 0. 角色

你负责迭代 AI Watch 手机端 App(Android)。手表端已实现:
- 自定义 GATT 服务(f1 Status / f2 TimeSync / f3 DataUpload / f4 Command),协议版本仍为 `0x01`。
- AI 助手页(菜单中心图标):Start 按钮经 f3 发出 AI 触发;收到 AI 结果后在手表页全量显示,并在手表顶部弹 banner(前约 8 个字符)。
- 收到 AI_TIMER 后启动本地倒计时(页面关闭也继续计时),到时弹 "Timer done" banner。

本次迭代目标:App 收到手表的 AI 触发后,完成"录音 → 语音识别 → LLM → 结构化结果 → 下发手表"的完整闭环。

## 1. 协议增量(全部向后兼容,靠"未知类型忽略")

### 1.1 上行:f3 DataUpload 新增 sensor_type 0x10 —— AI_TRIGGER

帧:`[version=1(1)][0x10(1)][source(1)][context(N)]`

- `source=0x01`:AI 助手页按钮,context 为空(0 字节)。
- `source=0x02`:心率/血氧页 Ask AI 按钮,context 固定 4 字节:`[hr(2, uint16 LE)][spo2(2, uint16 LE)]`,值为最近一次测量结果,**0 表示未知/无效**(传感器未就绪时也为 0)。
- 要求:**source 未知或 context 任意长度都必须容忍**,不崩溃。
- 处理:两种来源都进入同一语音流程;source=0x02 时 App 可在会话里显示携带的心率/血氧值(0 显示 --),并允许用户直接说"分析一下我的心率"。

### 1.2 下行:f4 Command 新增 cmd_type

帧头与 v1 相同:`[version(1)][cmd_type(1)][id(1)][flags(1)][timestamp(4, LE)][title_len(1)][title(N)]`

| cmd_type | 名称 | 字段语义 | 手表行为 |
|---|---|---|---|
| 0x04 | AI_TEXT | id=请求 id(非零);flags 传 0;timestamp=AI 生成时刻 UTC;title=AI 回复文本,UTF-8,**≤ 224 字节** | 全量显示在 AI 助手页;banner 显示截断副本 |
| 0x05 | AI_TIMER | id=计时 id(非零);flags 传 0;**timestamp 字段 = 时长秒(1..86400,不是 UTC!)**;title=倒计时名称,UTF-8 ≤ 24 字节 | 启动倒计时;再次发送即覆盖当前倒计时 |

约束与校验(手表严格执行,违反即拒绝):
- `title_len` 与帧长必须严格匹配(帧长 = 9 + title_len);AI_TEXT 超 224 字节、AI_TIMER 的时长越界都会被拒。
- id 为 0 的帧被拒。
- **发送 AI_TEXT 前必须已完成 MTU ≥ 247 协商**(最长帧 9+224=233 字节,超过默认 23-3=20 字节写上限)。
- 发送顺序:每个请求**先发 0x04(AI_TEXT),再发动作命令**;同一请求的 AI_TEXT 重发同 id 即覆盖。
- 当前版本手表无法被远程取消倒计时;CLEAR(0x03)只清提醒,不停止已开始的倒计时。

### 1.3 落地为提醒/通知:复用既有命令,无需新增

LLM 判定要"设提醒/发通知"时,直接按 v1 规范发 `0x01 REMINDER` / `0x02 NOTIFICATION`(id/flags/timestamp/title 语义不变)。

### 1.4 兼容性

- 老手机 App 收到 0x10 通知应按 v1 规范"未知 sensor_type 忽略";迭代时确认这条路径,不要因新类型崩溃。
- 手表对未知 cmd_type(≥0x06)打印并丢弃;未来再加类型时老手表同样忽略。
- **订阅 CCC 的取值**:手表的 Status(f1) 与 DataUpload(f3) 同时支持 Notify 与 Indicate——订阅写 `0x0001` 走通知,写 `0x0002` 手表自动降级为 Indication 应答,两者都能收到数据(此前的手机版本写 0x0002 导致收不到上行,已在手表端兼容;新版本建议统一写 0x0001)。

## 2. 手机端功能需求

### 2.1 AI 会话状态机

```
IDLE → LISTENING(收到 0x10,开始录音,VAD/静音或点停止结束)
     → RECOGNIZING(ASR)
     → THINKING(LLM)
     → DELIVERING(先 0x04,再逐个 actions)
     → IDLE
```

- 每步给用户可见状态("聆听中…/识别中…/思考中…/发送中…");录音中允许用户取消。
- 超时建议:录音 ≤ 15s、ASR/LLM 各 ≤ 20s、单帧写失败按既有错误策略重试(0x11 满 → 2s 退避)。
- 断连:任何阶段链路断开 → 停止流程并提示,不崩溃;重连成功后不自动重放旧请求。

### 2.2 ASR 与 LLM

- ASR:按 §2.3 配置(默认系统识别器,可切换模型服务);识别失败给用户重说入口。
- LLM:把识别文本与下述 system prompt 一起提交,**强制返回 JSON**,解析失败时把原始文本仅作为 AI_TEXT 发送(不带 actions)。

system prompt(可直接使用):

```
你是智能手表的语音助手。用户的话会转成文本给你。只输出一个 JSON 对象,不要输出任何其他文字:
{"reply": "<给用户的简短中文回复,不超过 70 个汉字>",
 "actions": [<0 个或多个动作>]}
动作只能是以下三种之一:
{"type":"create_reminder","title":"<提醒标题,不超过 8 个汉字>","trigger_utc":<触发时刻的 Unix 秒(UTC)>}
{"type":"start_timer","label":"<倒计时名称,不超过 8 个汉字>","duration_s":<1..86400 的整数>}
{"type":"notify","title":"<通知标题,不超过 8 个汉字>"}
规则:
1. 用户要"N 分钟/小时后做某事"→ 用 create_reminder(算出 trigger_utc),不要用 start_timer。
2. 用户要"N 分钟倒计时/计时"(如泡面、专注)→ 用 start_timer。
3. 只是闲聊、提问、需要解释 → actions 为空数组。
4. 回复要口语化、简短,适合手表屏幕。
当前时间:{utc ISO8601},时区偏移:{±分钟}。
```

- id 分配:request id(AI_TEXT 用)与 timer id 各自维护一个 1..255 循环计数器,不同命令空间互不复用;reminder id 沿用 v1 规则。

### 2.3 AI 服务配置(LLM / ASR / TTS 三组独立)

**总体**:三组服务各一套**独立**配置——LLM 必配;ASR、TTS 默认"系统自带",可切换为模型服务。主要适配 **Qwen 系列**与 **MiMo 系列**,接口统一为 OpenAI 兼容协议。

#### 2.3.1 配置组结构(设置页)

| 配置组 | 组成 | 默认 |
|---|---|---|
| LLM(必配) | Base URL 列表 + API Key + 模型名(可拉取)+ 测试按钮 | 无,未配置不可用 |
| ASR(可选) | 开关:系统自带 / 模型服务;模型服务下有独立 Base URL + Key + 模型名 + 测试 | 系统自带 SpeechRecognizer |
| TTS(可选) | 开关:系统自带 / 模型服务;模型服务下有独立 Base URL + Key + 模型名 + 测试 | 系统自带 TextToSpeech(手机本地播放) |

三组的 Key 独立保存(同服务商可填同一个);Key 输入框掩码,**不得明文写入日志**。

#### 2.3.2 Base URL:选择列表

不做自由输入为主;用**预置列表 + 自定义项**:

| 预置项 | Base URL | 适配系列 |
|---|---|---|
| 阿里云百炼(Qwen) | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen 系列 |
| MiMo 服务商 | 按实际服务商填(如硅基流动 `https://api.siliconflow.cn/v1`)或自建 OpenAI 兼容网关 | mimo 系列 |
| 自定义… | 选中后出现手输框 | 任意 OpenAI 兼容服务 |

列表项支持后续版本扩充;选中的 Base URL 是该配置组内三个功能(拉模型/测试/正式调用)的公共前缀。

#### 2.3.3 模型名获取

- 选定 Base URL 并填入 Key 后,提供"**刷新模型列表**"按钮:调用 `GET {base}/models`,把返回的模型 id 做成**下拉选择**,包含 `qwen` / `mimo` 字样的置顶并分组展示。
- 拉取失败(网络/权限/服务不支持该端点)→ 提示原因并**允许手动输入模型名**。
- 模型名参考(以实际拉取结果为准):LLM `qwen-flash` / `qwen-plus` / `MiMo-7B-RL`;ASR `qwen3-asr-flash`;TTS `qwen-tts` / `cosyvoice` 系列。

#### 2.3.4 可用性测试

每组配置提供"**测试**"按钮,点击后立即验证并显示结果(成功含耗时,失败含错误摘要):

- LLM:发一条最小 chat 请求(内容 "ping",`max_tokens=8`)。
- ASR:上传约 1 秒的短音频,期望返回(可空)文本。
- TTS:合成"测试"并本地播放。

测试未通过的组,对应功能入口置灰;LLM 组测试未通过时,收到手表触发后提示"AI 服务未就绪,请检查设置",不进入聆听。

#### 2.3.5 ASR / TTS 模型服务细则

- **ASR**:录音 16 kHz / 16 bit / 单声道(格式按所选服务要求,通常 WAV/PCM/MP3),整段上传 → 返回文本;识别失败给用户重说入口。
- **TTS**:回复文本 → TTS 模型 → 音频在**手机端**播放(手表端不做音频输出);TTS 失败不影响 AI_TEXT 下发,只是不播报。
- 系统自带模式零配置;切换到模型服务后,该组使用自己的 Base URL/Key/模型,与 LLM 组互不影响。

#### 2.3.6 调用参数与失败处理(沿用)

- LLM:温度 0.3~0.5;支持时开 `response_format={"type":"json_object"}`;容忍 ```` ```json ```` 代码围栏,解析失败按 §2.2 降级(只发文本、不带 actions)。
- LLM 调用失败/超时(≤20s):本次会话标记失败并提示重试;**不得把错误信息当作 AI 回复发给手表**。
- 联网与隐私:声明 INTERNET 权限;录音与识别文本、心率/血氧上下文只发往用户配置的服务。

### 2.4 UI

- AI 页:最近会话列表(时间、识别文本、AI 回复、已下发的动作及结果),失败项可一键重发。
- 设置页:新增 §2.3 的三组配置(LLM / ASR / TTS),含 Base URL 选择列表、"刷新模型列表"、"测试"按钮。
- 收到 source=0x01 触发时:若在前台直接进 LISTENING;若在后台,发一条高优先级通知点开即录(依赖已有的前台服务保活)。
- 既有功能(提醒管理、TimeSync、传感器仪表盘)不得回归。

## 3. 联调验收清单(手表烧 4.7.0)

1. 连接后手表 AI 页(菜单中心 AI 图标)→ 按 Start → 手机进入聆听 → 说"5 分钟后提醒我喝水" → 手表 banner 显示回复,提醒页出现该提醒(到时弹提醒 banner)。
2. 说"来个 1 分钟倒计时" → 手表 AI 页顶部出现 "Timer 01:00" 倒数,退出页面计时继续,到时弹 "Timer done"。
3. 说一段闲聊(无动作)→ 仅 banner + AI 页显示文本。
4. 未连接时按 Start → 手表显示 "BLE not connected",手机无感知。
5. 长回复(>24 字节)→ banner 截断处无乱码(UTF-8 边界),AI 页显示完整文本。
6. 心率页 Ask AI(麦克风图标按钮)→ 同样进入聆听流程;会话里显示携带的心率/血氧(未测量时显示 --)。
7. 服务配置:Base URL 从列表切换(百炼/MiMo 服务商/自定义)→ 填 Key → "刷新模型列表"能拉到模型(qwen/mimo 置顶)→ "测试"通过 → 正式对话成功。
8. 首次使用未配置 LLM → 提示去设置页;配置并测试通过后重试能正常返回结果。
9. TTS 开启模型服务 → 回复能在手机端播报;切回系统自带也正常;TTS 失败不影响手表收文本。
10. 回归:校时、提醒增删、传感器仪表盘、断连自动重连全部正常;心率页进/出不卡顿(手表端探测已线程化)。

## 4. 明确不做(本期)

- 手表端 TTS/扬声器、板载麦克风录音上行(带宽与驱动后续专项)。
- 心率页 Ask AI 的数据质量门控(当前按钮总是可按,context 未测量时传 0;待心率血氧实机打通后可改为仅在数据有效时允许)。
- 语音流式/免唤醒、多轮对话上下文(手表端无存储,每轮独立)。
