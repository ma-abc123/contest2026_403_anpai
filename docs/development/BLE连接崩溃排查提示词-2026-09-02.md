# 【求助】SF32LB52 蓝牙 LCPU 控制器固件在连接建立时断言崩溃——排查提示词

> 复制以下全文发给排查的同学即可。所有日志均为手表串口原文。

---

## 环境

- 硬件：立创·黄山派（LCKFB lckfb_huangshan_pi），SiFli **SF32LB52**，硅片 **revid=3**
- 系统：openvela/NuttX，BT host 为 zblue（external/zblue），H4 UART（/dev/ttyHCI0）接 LCPU 控制器
- 控制器补丁：SDK 按 `revid < HAL_CHIP_REV_ID_A4` 强制走 **legacy patch**（vendor/sifli/middleware/bluetooth/patch/sf32lb52/ 下的二进制 blob，选路代码在 vendor/sifli/chips/sf32lb52/sf32lb52_lcpu_boot.c: `rev_id < HAL_CHIP_REV_ID_A4 ? "legacy" : "rev_b"`）
- 应用：自研 AI Watch（LVGL 手表，自定义 GATT service：f1 Status/f2 TimeSync/f3 DataUpload/f4 Command）
- 关键 BT 配置：`CONFIG_BT_CLASSIC=y`、`CONFIG_BT_GATT_CLIENT=y`、`CONFIG_BT_GATT_DYNAMIC_DB=y`、`CONFIG_BT_PRIVACY=y`、`CONFIG_BT_H4=y`、`CONFIG_BT_AUTO_DATA_LEN_UPDATE=n`、`CONFIG_BT_GAP_AUTO_UPDATE_CONN_PARAMS=n`、`CONFIG_BT_GATT_CACHING=n`、`CONFIG_BT_NATIVE 未设置`

## 症状（100% 复现，4/4，跨两次手表重启、两个不同的手机端 App）

手机（任意 central，包括通用 BLE 调试工具，非仅我方 App）连接手表后 **0~2 秒内控制器断言崩溃**，连接立即断开：

## 已排除（附证据）

1. **我方应用层 BLE 代码**：B→C 的代码 diff 只有运动算法三处（cooldown/峰值记录/版本号字符串），不触碰任何 BLE/桥接代码；connected 回调只做 bt_conn_ref + 置状态，主机不发起任何 conn param/PHY/安全流程。
2. **我方 BLE 流量触发**：崩溃发生在任何一次成功的 indicate/notify 之前（首发 STEPS 在 CCC 写入前被 zblue 以 ENFORCE_SUBSCRIPTION 拒绝，没有产生空口报文）。
3. **heap arena 顶到 LCPU 邮箱窗口**（我们已知的 BT 流损坏陷阱）：工作/崩溃构建的 arena 完全相同（8457112 bytes）。
4. **手机 App 特有行为**：换用通用 BLE 工具同样必崩。

## 请教的问题

1. `lcpu evidence` 的断言签名（`ai=54b3f5ef d0fd15a1 aacb3edf 053c5c0f cfg=45457878 ...`）如何解码？指向哪个模块/哪类错误？
2. SF32LB52 revid=3（legacy patch）是否存在**连接建立阶段断言**的已知 errata？触发条件是什么（手机侧 DLE/PHY/conn param 更新请求？BR/EDR 并发？加密请求？）？
3. `rev_b` 补丁路径（revid≥A4 才启用）能否在 revid=3 上强制使用？是否有风险？是否有更新版本的 legacy patch blob（我们 SDK 内是该问题的唯一 blob）？
4. 恢复路径中 `L2CAP server registration failed -98` / `ATT BR Server registration failed -98`（EADDRINUSE）说明 bt_enable 重入时旧注册未清——这是已知问题吗？与反复崩溃有无关联？
5. 有无可尝试的配置开关规避（如 `CONFIG_BT_CLASSIC=n`、`CONFIG_BT_GATT_CLIENT=n`、`CONFIG_BT_PRIVACY=n`、`CONFIG_BT_NATIVE`）？我方可快速出验证固件。
