# 恢复反编译前的厂商原版 LCPU blob

## 范围与版本选择

用户要求测试撤销反编译修改，相关功能正常时保留原版。本轮保留已经
通过实机对照的共享环 MPU 非缓存修复，只恢复厂商指令和更新版本标识。

本次“原版”是 E1 实验修改前的 **同版本厂商 SDK blob，2040 words /
8160 B**。它与 `vendor/sifli/chips/drivers/cmsis/sf32lb52x/lcpu_patch.c`
的 `g_lcpu_patch_list` 和 `g_lcpu_patch_bin` 两个数组完全一致。
`middleware/bluetooth/patch/sf32lb52/sf32lb52_lcpu_patch.h` 是更早的
2024-word 版本，本轮没有进行这一额外降级。

核对 E1 与厂商同版本数组，数值差异恰好是 `g_lcpu_patch_bin[1164..1171]`
八个 word。原 E1 全为 `0xbf00bf00`（双 NOP），恢复的厂商值依次为：

```text
4680f04f f4406830 60302080 f7fa2005
6830f505 2080f420 20056030 f4fef7fa
```

`g_lcpu_patch_list` 62 words 未变。保留历史 `_exp.h` 文件名以避免复制
整份数组，文件头及 loader 注释已明确内容现在是厂商原版。

按小端字节序展开的数组 SHA256：

| 数组 | SHA256 |
|---|---|
| 62-word patch list | `a18868d4d8b2f3825982b6bc4c35325113c958545a6c710af0753c707ff7bf68` |
| 2040-word patch bin | `5e24c28991d852af8309dfebbb968d5bedf753688dab21a12c9f545b63f0aa92` |

## 验证

所有自动测试使用本机 BLE 适配器和板端串口，测试前停止
`ai-watch-viewer`，避免串口竞争。沿用共享环修复时的相同流程：

```bash
/usr/bin/python3 tools/ble_connect_test.py -n 5 --scan-s 20 --hold 45 \
  --gap 5 --load none --log-prefix /home/ma/huangshan-logs/ble_4881_vendor_none
/usr/bin/python3 tools/ble_adv_lottery.py -n 8 --scan-s 12 \
  --log-prefix /home/ma/huangshan-logs/ble_4881_vendor_boot8
/usr/bin/python3 tools/ble_connect_test.py -n 5 --scan-s 20 --hold 45 \
  --gap 5 --load frames --log-prefix /home/ma/huangshan-logs/ble_4881_vendor_frames
```

普通负载测试结果：4 轮 `SURVIVED`（每轮校时并保持 45 秒），第 5 轮
主机报 `BleakError: device 'dev_60_F3_82_6C_78_47' not found`，分类
`FAIL_CONN`；板端没有 Hardware Error、HCI 超时或 reason=0x00。
不能把第五轮主机错误记成成功，也没有证据据此归因为 LCPU blob。
完整结果位于 `~/huangshan-logs/ble_4881_vendor_none.results.json`。

用户随后要求停止自动测试、打开投屏自行测试。因此本轮未运行上述
8 次启动及持续投屏连接回归，不宣称完整验收通过。板上保留
`4.8.81-vendor-panel` 的同版本厂商原版 blob，`ai-watch-viewer` 已启动。
用户随后明确决定正式采用该厂商原版，并要求提交到个人 fork。
共享环 MPU 修复继续保留；原 E1 镜像及头文件备份保留供追溯。
