# 开发日志 2026-09-02：M4 运动与跌倒检测（4.8.0 → 4.8.3）

## 1. 目标与范围

对齐开发流程 M4：运动感知（计步/活动分类）+ 跌倒检测（合加速度幅值、姿态变化、冲击后静止、用户取消倒计时），只报告"疑似跌倒"、不宣称医疗级；测试集、阈值、误报/漏报记录于本文第 6 节。

## 2. 架构

新增 `app/ai_watch/ai_watch_motion.c/h`，**开机自启的后台 pthread**，与 UI 解耦：

- 线程独占 `/dev/lsm6dsl0`（板载 LSM6DS3TR-C @0x6A，BSP 已注册）：open → `SNIOC_START` → 25ms 轮询 `SNIOC_LSM6DSLSENSORREAD`；ioctl 失败关句柄退避重开
- 算法全部在线程内；结果写入 mutex 保护的快照 + 事件队列，主循环 `ai_watch_motion_process()`/`ai_watch_fall_poll()` 消费——LVGL 线程零 I2C 接触（复用 4.7.3 心率页沉淀的模式）
- 步数/活动窗口只在 NORMAL 态推进，冲击弹跳不污染统计

驱动接口事实（内置 lsm6dsl.c 为 bringup 级测试驱动）：

- 固定 833Hz ODR 双引擎，无 ODR/量程 ioctl；实测整环采样率 **~15Hz**（每次 `sensor_read` 走 22 次单字节寄存器读，~42ms）——冲击峰值有欠采样风险，是阈值放宽的依据之一
- 读出已换算：accel mg（0.488/LSB @±16g）、gyro mdps（70/LSB @2000dps）
- `SNIOC_START_SELFTEST` 会污染全局换算因子（g_accelerofactor→0.122/1000），禁用

## 3. 算法与阈值演化

### 3.1 计步与活动

- 计步：|a| 迟滞检测（峰 >1150mg / 谷 <850mg），不应期 300ms，步长 0.7m 估距离；日累计（RAM，重启清零）
- 活动：2s 滑窗标准差，<30mg 静止 / >350mg 跑步 / 其余步行，同级 ~1s 防抖后发布

### 3.2 跌倒判定（阈值演化表）

| 参数 | 4.8.0 初值 | 最终 (4.8.2) | 修正依据 |
|---|---|---|---|
| 冲击-硬（单点） | 2800mg | **2400mg** | 实测重砸 2614mg 差点漏过 |
| 冲击-软（需条件） | 2200mg 两连点 | **2000mg**，且自由落体后 500ms 内单点也计 | 跌倒#2 峰值 2185mg 漏报 |
| 自由落体 | <400mg 且持续 ≥60ms | **<550mg 单样本即锁存** | 15Hz 下短自由落体只采到 1 个样本，时长门限永不满足 |
| 静止窗 | 3s，末 1s 波动 <80mg | 同左 | — |
| 姿态变化 | ≥50° | ≥50°（保留） | 磕桌/放桌上方向不变，此门是防误报核心 |
| 平落备用路径 | 无 | **自由落体 + 落后静止 ≥4.5s**（观测预算 10s） | 跌倒#2 平落不转身（夹角仅 27°），角度路径永远抓不到 |
| 拒绝后冷却 | 60s | **8s**（告警后仍 60s） | "砸→拿起→再砸"测试节奏被盲区吞掉 |

任一路径确认 → `FALL_STATE_ALARM`：全屏红色倒计时 15s（lv_layer_top 模态层），触摸 CANCEL 或 KEY2 取消；超时发 FALL_EVENT 上报 + 常驻条幅。取消也上报（event 区分 1=确认/2=已取消/3=测试）。UI 与上报文案统一"**疑似跌倒**"。

## 4. 三轮实测修正（根因记录）

### 4.1 触控冻结（4.8.0，日志 ai-watch-20260901-*.log）

REC 时间戳节拍显示每第 4 条样本（即每条 BLE 帧）主循环停顿 ~120ms：**`bt_gatt_indicate` 在本移植上同步等待确认，一次阻塞约一个连接间隔**。录制时 ~6 帧/s，主循环 60-70% 时间被吃掉，LVGL 触摸采样失效（KEY2 为 GPIO 轮询所以幸存）。连带 bug：连接后 CCC 未写时 STEPS 首发失败被每轮重试，刷出 119 条 "Device is not subscribed" 内核告警。

修复（4.8.1）：`ai_watch_ble_post()`——48 深度帧队列 + 专用 TX 线程，失败退避 2s；DHT/心率页的上报一并迁移；仅 AI 触发保留同步（按钮需同步反馈）。

### 4.2 真跌倒不弹全屏告警（4.8.2，日志 ai-watch-20260902-080255.log）

固件日志 `impact 3936 mg` 后 `impact but orientation kept (34 deg)`：跌倒被角度门拒绝。根因：跌倒前姿态基准用慢速重力滤波，**初值 (0,0,1) 在 mg 量纲世界几乎为零，且 τ≈6.7s——会话开始 2.1s 即倒下，基准仅收敛 28%**，算出的"跌倒前方向"是垃圾值。离线分析脚本初值碰巧写对（0,0,1000）报 131°，暴露脚本与固件不同源。

修复：基准改用快速重力向量（α=0.15，~1s 收敛），初值 (0,0,1000)；分析脚本同步为固件精确镜像（后续离线调参才可信）。

### 4.3 重砸拿起未触发（4.8.3，日志 ai-watch-20260902-083949.log）

两次重砸均被看到（impact 2614mg, ff=yes），但砸后 0.15~0.3s 即拿起，静止门从未满足 → `impact followed by motion`，**正确拒绝**（与"拿表磕桌"不可区分）。衍生修正：拒绝后冷却 60s→8s；上报冲击值改为记录 IMPACT 期间真实峰值（原为首过阈样本）。

## 5. 数据采集与离线分析（M4 顺序的"先离线后上板"）

- 手表端：Exercise 页 Record 按钮，线程内捕获入队，主循环串口全量 CSV（`REC,t_ms,x,y,z,gx,gy,gz`，~15Hz）+ BLE 抽样转发（0x12，1/4 抽样）
- 离线：`tools/fall_threshold_analysis.py` 将串口日志按 t_ms 归零自动分会话，**用与固件相同的状态机回灌**，输出每组 |a| 统计、事件（时刻/冲击/角度）与 PASS/FAIL（文件名含 "fall" = 期望触发）；阈值全部有同名 CLI 参数可直接扫描调优
