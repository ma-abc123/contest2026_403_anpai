## 1. 新终端先固定工具链

每次打开新终端后，先执行以下命令。不要省略这一步，否则可能使用 Ubuntu apt 安装的 GCC 10.3，导致 LLVM 17 libc++ 编译失败。

```bash
export PATH="$HOME/opt/arm-gnu-toolchain-14.2.rel1-x86_64-arm-none-eabi/bin:$PATH"
export PATH="$HOME/.local/bin:$PATH"

command -v arm-none-eabi-gcc
arm-none-eabi-gcc --version | head -1
command -v olddefconfig
command -v menuconfig
command -v savedefconfig
cmake --version | head -1
ninja --version
```

验收：

- [ ] `arm-none-eabi-gcc` 路径位于 `$HOME/opt/arm-gnu-toolchain-14.2.rel1-x86_64-arm-none-eabi/bin/`。
- [ ] 版本显示 `14.2.1`。
- [ ] `olddefconfig`、`menuconfig` 和 `savedefconfig` 均能找到。

如果 GCC 不是 14.2.1，立即停止，不要开始 CMake 配置或编译。

## 9. 使用正确的串口参数验收

Picocom 必须带 `--omap crlf`，否则终端中回车可能无法执行 NSH 命令。

```bash
mkdir -p "$HOME/huangshan-logs"

picocom \
  --omap crlf \
  -b 1000000 \
  --noreset \
  --lower-dtr \
  --lower-rts \
  --logfile "$HOME/huangshan-logs/ai-watch-$(date +%Y%m%d-%H%M%S).log" \
  "$SF32_PORT"
```

进入 `nsh>` 后执行：

```text
nsh> ps
```

如果 Lyra `vapp` 已自动启动，确认其数字 PID 后停止它：

```text
nsh> kill -15 <vapp 的数字 PID>
nsh> ps
```

然后运行项目应用：

```text
nsh> ai_watch
```

- [x] 串口输出应用名称和版本。
- [x] 串口输出 `ai_watch started` 或含义等价的启动成功信息。
- [x] 无 assertion、hard fault、崩溃或异常重启。
- [ ] 串口日志已保存到 `$HOME/huangshan-logs/`。
