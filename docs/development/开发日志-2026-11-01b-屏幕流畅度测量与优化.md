# 开发日志 2026-11-01b —— 屏幕流畅度测量与第一轮优化（4.8.57-perf1~perf5）

> 插队任务：在进入 P2 端侧模型前，量化屏幕链路瓶颈并吃掉便宜的优化。
> 锚点 `anchor-ui5-20261101` 之后的第一个专项。板子为坏屏状态，
> **headless 渲染**（见 §4，这决定了本次能测什么、不能测什么）。

## 1. 测量基建（保留在固件里）

- `CONFIG_LV_USE_SYSMON/PERF_MONITOR/PERF_MONITOR_LOG_MODE=y` +
  `LV_LOG_PRINTF=y` + `LV_LOG_LEVEL_INFO=y`：每秒一条 sysmon 行。
  **注意**：sysmon 的 FPS/render/flush 字段在本端口上一半是 0（统计钩子
  没接全），只有 refr_cnt/refr_rate 可参考。
- 应用侧 **UIPERF**（`ui_perf_event_cb`，LV_EVENT_ALL 挂在 display 上）：
  每秒打印 `UIPERF refr=N dirty=K`——真实刷新周期数 + 作废像素量。
  这是本次唯一完全可信的指标。
- 测量脚本 `~/huangshan-logs/measure_perf.py <tag>`：四场景（表盘静置/
  菜单拖拽/负一屏滚动/页面切换）自动注入 + 控制台分场景落盘。

## 2. 根因链（每步都有实测）

1. **LVGL 端口给的是整屏缓冲 + RENDER_MODE_FULL**
   （`LV_NUTTX_LCD_BUFFER_COUNT=1` → `lv_nuttx_lcd.c`）：任何一次作废
   都全量重绘 351KB 并全量搬运。headless 分支注释早已量化：FULL 模式
   单次作废 **100-180ms**，一次点击能把主循环拖慢 10 倍。
2. **默认 33ms 刷新周期不成立**——defconfig 早已是
   `CONFIG_LV_DEF_REFR_PERIOD=16`（本次才核实），刷新节拍不是瓶颈。
3. **DIRECT 模式（perf2）**：整屏缓冲保留（投屏快照源不变），但只重绘
   脏区。滚动渲染 100-180ms → **88ms**。
4. **88ms 的真正成分（perf4 定位）**：整屏缓冲 351KB 在 lv_malloc 里
   落 **PSRAM**（SRAM 堆富余 ~200KB 装不下），LVGL 经 QSPI 总线渲染
   只有 **~4MB/s**。SRAM 条带（perf4，.bss 静态 60 行 + aligned(64)）
   后渲染 73ms——提升有限，说明**LVGL 软渲染器本身吞吐 ≈10Mpx/s**
   （圆角遮罩 + alpha 混合逐像素），内存只是一部分。
5. **-O3 专编 LVGL（perf5，`CONFIG_LV_OPTLEVEL="-O3"`）**：菜单场景
   refr_rate 8→13，滚动总帧时下降；绝对值仍受每帧脏区量支配。

## 3. 最终方案（4.8.57-perf5，全部保留在固件里）

- **PARTIAL 条带渲染**：静态 .bss 条带 `g_lcd_strip`（390×60 RGB565，
  46.8KB，`aligned(64)` 保证 SRAM）+ `LV_DISPLAY_RENDER_MODE_PARTIAL`
  ——只渲染/搬运作废区域。
- **影子帧**：`g_lcd_shadow`（351KB，PSRAM）——flush 回调把每条条带
  memcpy 进影子帧的对应位置，投屏快照改读影子帧
  （`ai_watch_shot_bind_frame`）。**投屏功能完好**（perf5 镜像/负一屏
  截图验证）。PARTIAL 模式下 LVGL 自己的缓冲只有一条条带，没有影子
  投屏就废了——这是两者必须绑在一起的原因。
- flush 回调 `ai_watch_lcd_flush_cb`：有 LCD 设备时 PUTAREA 上屏
  （真屏路径），headless 跳过 ioctl 只做影子拷贝。
- 输入扫描 30→15ms（`lv_indev_get_read_timer` + `lv_timer_set_period`）。
- **踩坑**：`lv_display_set_buffers` 对 draw buffer 有对齐断言
  （`LV_DRAW_BUF_ALIGN`，本配置 4 字节；uint16_t 静态数组可能只对齐
  2 字节）——必须 `__attribute__((aligned(64)))`，否则开机即
  lv_assert 循环。
- 改 defconfig 后重配置**不生效**的坑：NuttX cmake 只在 `.config`
  不存在时才从 defconfig 重新生成（`cmake_out/prod/defconfig` 暂存
  副本同理）——改 defconfig 后必须删 `.config` 再重配置。

## 4. headless 的关键认识（坏屏板的测量边界）

坏屏板整机运行在 **headless 渲染**（`AI_WATCH_HEADLESS=1` 写死在
main.c）：没有面板写、没有 QSPI2 流量，投屏读的是渲染缓冲。因此：

- 本轮测到的 88ms/73ms 等全部是**纯渲染成本**；真机（好屏）上还要叠
  加 QSPI2@50MHz 的搬运（全屏一帧 ~15-25ms）。
- 好屏机器上的完整瓶颈模型：渲染（本轮已优化：FULL→PARTIAL+SRAM）
  + 搬运（脏区越大越多）+ TE 同步。修好屏幕或换健康板后需要重测。
- "60fps 全屏动画"在真机上仍受 QSPI2 带宽物理上限（全屏 ~40-50fps），
  但**部分渲染后日常场景（走秒/小组件）脏区极小，60fps 节拍可达**；
  滚动/切页动画的目标应定为稳定 30fps。

## 5. 数据总表（UIPERF 可信指标 + sysmon 参考）

| 场景 | perf2（DIRECT+PSRAM整屏） | perf5（PARTIAL+SRAM条带+O3） |
|---|---|---|
| 表盘静置 | refr~50/s **dirty=0**（时钟未同步时静态） | 同左（零成本） |
| 负一屏滚动 | refr 16/s，dirty ~11.6Mpx/s，render 88ms | refr 11-23/s，dirty 1.8-3.7Mpx/s，render ~55-90ms |
| 页面切换 | sysmon refr_rate 50（无渲染时） | 同左 |

滚动脏区 ~1-2 屏/帧是 LVGL 滚动的固有代价（滚动=整块内容区域作废）。
跨运行对比受拖拽动力学影响，绝对值看单次日志。

## 6. 遗留与下一步

1. **渲染吞吐**：LVGL SW ≈10Mpx/s 是下一瓶颈。候选：逐 draw-unit 拆分
   （单核收益有限）、滚动内容减负（圆角/阴影在滚动时的代价）、
   PPA/LCDC 硬件 blit 探索（SF32LB52 有 2D 加速块，未评估）。
2. **真机重测**：好屏板/修屏后重跑本脚本，补面板搬运与 TE 数据。
3. sysmon 统计钩子修复（render/flush 计时为 0）属公共仓改动，低优先。
4. 版本：板上现为 **4.8.57-perf5**（含测量仪表，log 每秒一条，无碍
   日常）；验收后与本轮 app 改动一并提交。
