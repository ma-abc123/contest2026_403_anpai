## 1. Phase 1: BLE 手机连接与时间同步

### 完成状态：⚠️ 代码完成，实机验证待完成

### 实现架构

SiFli BSP 使用 zblue（Zephyr BLE 栈），NuttX 原生 BLE 栈不可用。通过 BSP 弱钩子注册自定义 GATT 服务。

```
sf32lb52_bth4.c (vendor/sifli)
  └── sf32lb52_bt_initialize()
        └── sf32lb52_bt_register_custom_services()  ← 弱钩子

ai_watch_ble.c (contest repo)
  └── sf32lb52_bt_register_custom_services()  ← 强实现
        └── bt_gatt_service_register_mc(0, &g_ai_service)
```

### GATT 服务

```
Service UUID: 12345678-9abc-def0-1234-56789abcdef0

├── Status (f1): Read + Notify, 6 字节
├── TimeSync (f2): Write, 7 字节, 严格校验
├── DataUpload (f3): Notify
└── Command (f4): Write — 手机→手表数据通道
```

### 时间同步协议

| 偏移 | 长度 | 字段 | 校验 |
|---|---|---|---|
| 0 | 1 | 版本号 | 必须 =1 |
| 1 | 4 | UTC Unix 秒 | ∈[2020, 2100) |
| 5 | 2 | 时区偏移(分钟) | ∈[-720, +840] |

- nRF Connect 扫描发现服务
- 写入时间同步特征，验证 RTC 更新

## 2. Phase 2: 提醒、日程与通知应用

### 完成状态：✅ 代码完成

### 数据协议

通过 BLE Command 特征 (f4) 接收数据：

```
[version(1)] [cmd_type(1)] [id(1)] [flags(1)] [timestamp(4)] [title_len(1)] [title(N)]

cmd_type:
  0x01 = 提醒
  0x02 = 通知
  0x03 = 清除全部

flags:
  bit0 = 已读
  bit1 = 活跃
```

### UI

- 列表显示最多8条提醒
- 未读标记（眼睛图标）
- 空状态提示"Waiting for data from phone..."
- 500ms 刷新间隔

## 4. Phase 4: DHT22 温湿度功能

### 完成状态：✅ 代码完成，硬件接线待确认

### 实现

- 尝试打开 `/dev/dhtxx0`（NuttX dhtxx 驱动）
- 成功：显示温度、湿度、采样时间
- 失败：显示"Sensor unavailable"（不显示假数据）
- 2 秒采样周期
- **BLE 数据上传**：温度和湿度通过 DataUpload 特征通知手机

### BLE 传感器数据格式

```
[version(1)] [sensor_type(1)] [payload(N)]

sensor_type:
  0x01 = temperature (float, 4 bytes, little-endian)
  0x02 = humidity (float, 4 bytes, little-endian)
  0x03 = heart rate (int16, 2 bytes, little-endian)
  0x04 = spo2 (int16, 2 bytes, little-endian)
```

### 需要确认的硬件信息

| 驱动配置 | 需要 `CONFIG_SENSORS_DHTXX=y` 和 GPIO 配置 |
