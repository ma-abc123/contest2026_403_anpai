# 跌倒数据采集操作卡（2026-11-03）

> 用途：采一轮"真跌倒 + 误报动作"的六轴原始数据，用来定位"拿起动一动再放下
> 就触发跌倒"的误报成因，并作为阈值改动的离线验证集。
> 板上固件换成一个专属采集版（4.8.63-capture），采完烧回正常版即可。

## 0. 三个固件的用途

| 文件 | 版本 | 用途 |
|---|---|---|
| `~/huangshan-logs/bin_4862_nostore.bin` | 4.8.62-nostore | **正常演示固件**（headless，拔屏 + 投屏） |
| `~/huangshan-logs/bin_4863_capture.bin` | 4.8.63-capture | **采集固件**（上电即连续输出 REC） |
| `~/huangshan-logs/bin_4862_panelmode.bin` | 4.8.62-nostore（面板模式） | 明天新屏到货后烧这个 |

烧录命令（路径必须绝对，`/dev/ttyUSB0` 上不要有别的进程占着）：

```bash
systemctl --user stop ai-watch-viewer          # 必须先停投屏，否则串口被占
sftool -c SF32LB52 -p /dev/ttyUSB0 -b 1000000 \
  --before default_reset --after soft_reset \
  write_flash /home/ma/huangshan-logs/bin_4863_capture.bin@0x12010000
```

## 1. 采集流程

采集固件的行为：**上电就开始连续记录，不需要按任何键**。串口每秒滚出约
25 行 `REC,<t_ms>,<x_mg>,<y_mg>,<z_mg>,<gx>,<gy>,<gz>`，每 5 秒一行
`CAP,alive,<t_ms>,<样本数>` 心跳——看到心跳就说明流是活的。

```bash
# 一条命令：复位板子 → 抓 200 秒串口 → 存成文件
/usr/bin/python3 ~/huangshan-logs/grab_boot.py ~/huangshan-logs/cap_run1.log 200
```

**时间轴（严格按顺序，动作之间留 3 秒间隔）**

| 时间 | 动作 | 期望 |
|---|---|---|
| 0–30 s | 静置：手表戴手上，手臂自然下垂不动 | 无事件 |
| 30–35 s | 从桌上拿起手表 → 戴上 | **不应**检出 |
| 38–43 s | 站立 → 侧倒在床垫上 | 应检出 |
| 46–51 s | 站立 → 前倒在床垫上 | 应检出 |
| 54–59 s | 站立 → 后倒在床垫上 | 应检出 |
| 62–67 s | 快速坐下（椅子） | **不应**检出 |
| 70–75 s | 重重坐下（屁股砸椅子） | **不应**检出 |
| 78–83 s | 用手拍打手表 3 下 | **不应**检出 |
| 86–91 s | 原地跳 2 下 | **不应**检出 |
| 94–99 s | 正常走路 5 秒 | **不应**检出 |
| 102–107 s | 脱下手表放到桌上 | **不应**检出 |
| 110–115 s | 从桌上拿起 → 戴上 | **不应**检出 |
| 118–123 s | 侧倒（第二次，重复验证） | 应检出 |
| 126–131 s | 前倒（第二次） | 应检出 |
| 134–139 s | 拿起放下（第三次，误报复现） | **不应**检出 |
| 142–160 s | 静置收尾 | 无事件 |

## 2. 三个注意点

1. **手表必须戴在手上做动作**，不要拿在手里甩——目标场景是佩戴状态，拿在手里
   的加速度特征完全不同，采了也不能用来调参。
2. **跌倒只往床垫/软垫上倒**，不要硬地真摔。今天采的是特征分布，不是破坏力。
3. **USB 线放松**：线从身侧自然垂下，不要绷紧。线绷紧会拉住自由落体、缓冲冲击
   峰值，这是本轮采集唯一的系统性误差来源。每个动作重复 3 次就是为了在分析时
   看方差——某个动作三次差异特别大，我就把那一组剔除。

## 3. 采完做什么

1. 把 `~/huangshan-logs/cap_run1.log` 给我（我按时间轴切分、量特征）。

## 4. 已知的干扰项（采到了不用管）

- **BLE 控制器 recovery**：采集期间可能刷
  `aiwatch-ble: controller recovery type=command-timeout`，这是连续烧录多次
  触发的 LCPU「剂量」问题，会在 REC 序列里造成个别 300 ms 的间隔跳变。
  boot 后先静置 30 秒再开始动作就是为了避开它。
- **告警 UI 在采集版里是关的**：跌倒状态机照常判定、照常打日志
  （`MOTION: fall armed` / `impact but orientation kept`），只是不弹那 15 秒
  全屏倒计时——否则误报一次就把后面的动作全挡住。
- **有效采样率 25 Hz**（间隔稳定 40 ms）：配置写的是 25 ms，`usleep` 在本板
  tick 精度下实际是 40 ms。正常固件也是这个速率，所以采集数据与真实运行一致；
  离线回灌按真实 `t_ms` 计算，不假设固定周期。
