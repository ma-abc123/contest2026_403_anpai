# 开发日志 2026-11-01 —— 负一屏天气卡（28px/℃/滚动）与 LVGL 对象致盲 BLE 排查

固件 4.8.55-ble9 → **4.8.56-ui5**（contest 仓，未提交待验收）。
vendor/sifli 一处配套修改（`sifli_allocateheap.c`，未提交）。

## 需求

用户对负一屏（AI 简报页）三项不满：

1. 天气文字太小（16px），且"23°C"的度圈不显示；
2. 天气要有独立卡片，放页面靠上位置；
3. 负一屏要能上下滚动。

## 改动（contest 仓 app/ai_watch/）

- **字体**：新增 `fonts/ai_watch_font_weather_28.c/h`——28px 微型字体（ASCII +
  晴多云阴雨雪雾 7 字 + ℃），全字表 28px 约需 1MB flash，微子集只有几 KB。
  `gen_cjk_font.sh` 增加该字体生成段。
- **负一屏布局**：天气卡（样式化 label，见下）置于标题下方 y=58；统计卡/
  待办/点评卡整体下移；内容底 505px > 屏 450px → 屏幕开启 `LV_DIR_VER`
  滚动（滚动条隐藏）；"返回 (KEY2)" 提示移到 y=486。
- **滚动实现**：LVGL 自带拖拽滚动经远程指针 indev **从不触发**（verbose
  [PTR] 轨迹证明 press/move/release 全部到达但屏幕纹丝不动）。改为触摸
  轮询器驱动：非 HOME 页拖动分支里，`current_page==BRIEF` 且纵向意图时
  `lv_obj_scroll_by(screen, 0, target-cur, LV_ANIM_OFF)`，target 手动钳制
  在 [0, AI_WATCH_BRIEF_SCROLL_MAX=60]。**坑**：本 LVGL 的
  `lv_obj_get_scroll_y()` 返回**下滚量的相反数**（滚下 19px 读到 -19），
  直接回喂会每轮翻倍直至 -16977 冲出内容区（三帧全黑实证）；必须取负。
- **版本**：4.8.56-ui5。

## 三个独立 bug 及根因

### 1. 度圈消失 + 字符表踩坑（fonts/）

- 根因链：cjk_charset.txt 声称含 °(U+00B0)/℃(U+2103)，但唯一 CJK 源
  **DroidSansFallbackFull 没有这两个字形**；lv_font_conv 对"部分缺失"
  静默丢弃（仅对全空区段报错）→ 16px 字体里根本没有 °。
- 二次踩坑：把 °℃ 从 Droid symbols 里剔除时用了 `tr -d`——**tr 按字节
  删**，° 的 UTF-8 尾字节 0xB0 正是"数"(E6 95 B0) 的尾字节、℃ 含 0x84
  正是"评"(E8 AF 84) 的中间字节 → 半个字符表被静默损坏，"步数""点评"
  出现方块。**必须用 python 按字符剔除**。
- 修复：`-r 0xB0 -r 0x2103` 显式从 DejaVu 取；且**两个码位绝不能同时
  出现在 DejaVu -r 与 Droid --symbols**（后请求者胜出，Droid 缺字形则
  整个丢弃——实测复现）。换用单字形 ℃（U+2103）替代 °+C。

### 2. 负一屏滚动（见上）——get_scroll_y 符号 + 轮询器驱动

### 3. 【重大】新增 2 个 LVGL 对象致盲 BLE bring-up

现象：负一屏天气卡用 `lv_obj_create` 容器 + 2 个 label 实现后，
**每个 boot 的 bt_enable 必然 -110**（HCI_RESET 后 LCPU 不再应答，
0x0C03 command timeout，自愈重试也失败），整机 BLE 完全不可用。
恢复旧布局（1 个 label）则 3/3~5/5 boot 正常广播。

二分结论（每步 2~6 个 boot 交错验证）：

| 变量 | 结果 |
|---|---|
| 16px 字体重生成（+° ℃ 字形） | 无罪 |
| 28px 天气字体（+8KB rodata） | 无罪（gc 掉仍挂） |
| 提示字符串"连接手机后显示天气" | 无罪（置空仍挂） |
| 系统堆余量 | 7.4MB 空闲，页面开销 17KB——堆耗尽无罪 |
| 堆顶保留区 0x500→0x1000（vendor） | 未治愈（但保留，见下） |
| **卡片容器 +2 个 LVGL 对象** | **唯一相关变量，0/~20 boot 全挂** |

机制未完全查明。相关已知事实：SRAM 顶端 0x2007FB00-0x2007FFFF 是
HCPU_CUSTOM_CONFIG + HPSYS_MBOX_BUF（BT HCI 流固定地址，LCPU 从自己
地址空间读）；`sifli_allocateheap.c` 注释明言"堆分配到达该窗口会损坏
BT 流"。堆结束固定在 0x2007FB00，对象分配本身不可能碰到窗口；怀疑
方向是对象分配改变堆相位后，某个驱动 DMA/写越界落进窗口（vendor 侧
问题，需要 vendor 团队用 CC 对照定位）。

**修复（绕行）**：天气卡改为**单个样式化 label**（背景/边框/圆角/
内边距都设在 label 上，hint 与数据态共用一个 label 切字体颜色），
页面对象数与 4.8.55 完全持平 → BLE 立即恢复。**红线教训：改任何页面
的对象数量，必须跑 boot 广播回归；"UI 改动不可能影响 BLE"在板上不成立。**

vendor 配套（独立提交，勿混入应用改动）：`HCPU_TOP_RESERVED 0x500 →
0x1000`，给堆顶与配置/邮箱窗口之间垫 2.8KB 余量，防常规分配漂移。

## 联调备注（给手机端/后续自动化）

- 板子广播只持续**开机后约 15-30 秒**，主机扫描必须紧跟 boot（串口
  ready 前就开扫）；广告地址每次 boot 可能变化，按广播名发现。
- **触摸/翻页会打开 4.8.46 的连接窗口、暂停广播**——扫描期间不要注入
  任何触摸，否则主机侧完全看不到设备（实测多次复现）。
- 管道驱动的 bluetoothctl（Popen + 交互 stdin）收不到广播事件，
  `bluetoothctl --timeout N scan on` 子进程模式可用；MAC 正则是
  6 组冒号对（`{2}(?::…{2}){5}`，写成 {6} 会永远解析失败）。
- 手工测试帧（来自需求文档联调节）：
  `01 06 E1100000 2500 00 01 17 12 + "今天走得不错"UTF-8`。
