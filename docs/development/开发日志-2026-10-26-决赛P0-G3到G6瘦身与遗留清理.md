## 3. 两颗新雷与根因（08-30 历史轮没有的）

1. **G3 雷：FEATURE_FRAMEWORK 的 prompt 模块无条件依赖 freetype。**
   `apps/frameworks/runtimes/feature/modules/prompt/font.cpp:53` 直接调用
   `vg_font_create(..., (lv_freetype_font_style_t)style_)`，LV_USE_FREETYPE 关闭后符号消失，编译即炸。
   08-30 轮没踩到是因为 prompt 模块当时尚不存在（frameworks 仓在 dev-ai-contest-2026 线上后续新增）。
   处置：`CONFIG_FEATURE_FRAMEWORK`、`CONFIG_UIKIT` 随 G3 连带关闭——两者均为 defconfig 里
   quickapp 时代的直接残留（无任何 Kconfig select 它们），本应用（裸 LVGL + 自有框架）零消费者，
   链接层本就 Δ0（map 仅剩 LOAD 行）。
2. **G6 雷：yoga 是 C++，LIBCXX 关闭后连标准头都拿不到。**
   `YGNode/CompactValue` 包含 `<limits>`/`<type_traits>`，`-nostdinc++` 下 fatal error。
   08-30 轮 yoga 幸存是因当时 LIBCXX 还在编（如今它的链接贡献也早已被 gc 归零，只剩编译面）。
   处置：`CONFIG_LIB_YOGA` 随 G6 连带关闭。注意 `LIBUV` 保留——`LV_USE_NUTTX_LIBUV` 是 LVGL 的依赖，不能跟风关。

计划表中"QUICKJS/RAPIDJSON 无需单独关"的判断本轮复核仍成立：纯 C / 无人编译，链接 Δ0。

## 5. 试验组 T1（ALLSYMS+ELF）——上板失败，已弃

构建一次通过（binfmt/preapps 链接期担忧未成真），数字可观：bin 2,387,164 B（-153KB）、
data 61,900→16,044（-46KB）、bss 持平；map 中 allsyms 符号归零。**但上板判负**：

- 首烧观察：init wedge 风暴不停——单 boot 22+ 次恢复（0x1001/0x1003/0x1009 轮转，
  后段转为 init-failed -105），INIT_FAILED 自动重试（30s×5）也冲不出去，始终未出广播。
- 用户拔插复测多次，同样起不来——多 boot 一致，非单次运气差。
- 对照：同夜 4.8.23-p02（ALLSYMS/ELF 在编）每次启动最多 9 次恢复必出广播；
  回退复测后立即恢复（2~3 次自愈→广播→连接→校时全通）。

**结论：按计划"失败即弃"。** ALLSYMS+ELF 关闭与本板 BLE bring-up 存在稳定相关性；
机制不再深究（伴生变量 data 段 -46KB 布局位移最可疑；邮箱窗口为固定地址保留区，
不受堆布局影响——真因在别处）。工作树已还原，`cmake_out/bins/4.8.24-t1-trial.bin`
仅留档。**此配置组合后续勿再单独尝试**（已入 playbook 红线）。

勘误：§4 中"4.8.23-p02 一次点亮 init 零 wedge"系日志 head 截断误读，实际该 boot
有 9 次已知形态自愈后出广播（与历史分布一致）。

## 6. 教训

1. **历史瘦身结论要重新验证"编译面"而不只看"链接面"**：计划表按链接 Δ0 留置的
   FEATURE_FRAMEWORK/UIKIT/YOGA，在 freetype/libcxx 先后关闭后依次变成编译雷——
   "留置安全"的前提（上游不再新增对它们的强依赖）会随上游推进失效。
2. awk 分段统计用 `NR>=found` 在首次匹配前恒真（found 未置位时按 0 比较），把全量历史
   日志当成了本次启动——一度误判 64 次"恢复风暴"。分段统计必须用置位标志 `{f=1} f`。
3. 旧构建目录（1.9G×2）占满 96% 磁盘前先清；单目录逐组重配 + bin 拷出留存即可兼顾磁盘与二分。
