# 手机端需求：每日简报（DAILY_BRIEF）与天气同步

> 面向 `phone/` 目录里的 Android App（Kotlin / Compose）。
> 固件侧已实现：命令 0x06 解析、负一屏渲染、无手机时的本地兜底。
> 本文只描述手机端要做什么，不需要改固件。

## 一、这个功能解决什么

手表左滑有一块「每日简报」页，显示当天的步数、活动时长、跌倒次数、天气，
以及一句 AI 点评。

**前四项手表自己就能算**（步数/活动/跌倒来自运动服务，天气没有手机就没有）。
**只有那句点评必须手机生成**——手机有 LLM、有账号、有网络，手表没有。

所以手机端的职责很窄：**算出天气 + 生成一句话，打包发给手表。**

## 二、协议

### 2.1 走哪条路

复用现有的 **RX 命令特征**（手机 → 手表），和 `AI_TEXT` / `AI_TIMER` 同一条。
不需要新增 GATT 特征。

### 2.2 帧格式

```
偏移  长度  字段
 0     1    version = 0x01（与现有命令同一个 AI_WATCH_BLE_PROTOCOL_VERSION）
 1     1    cmd_type = 0x06  (AI_WATCH_BLE_CMD_DAILY_BRIEF)
 2     4    steps        当天步数，uint32 LE
 6     2    active_min   活动分钟，uint16 LE
 8     1    falls        疑似跌倒次数，uint8
 9     1    weather      天气码，见 2.3
10     1    temp_c       温度，int8（-128..127，摄氏度，负数用补码）
11     1    text_len     评语字节数，0..120
12     N    text         评语，UTF-8，无结尾 \0
```

**总长 = 12 + text_len，上限 132 字节。** 现有命令通道的写入上限是 240 字节，
留有余量。

### 2.3 天气码

| 值 | 含义 | 建议图标 |
|---|---|---|
| 0 | 未知 / 无数据 | — |
| 1 | 晴 | ☀ |
| 2 | 多云 | ⛅ |
| 3 | 阴 | ☁ |
| 4 | 雨 | 🌧 |
| 5 | 雪 | ❄ |
| 6 | 雾 | 🌫 |

手表只认这 7 个值，**超出范围按 0 处理（不显示天气）**。

### 2.4 评语约束

- **必须 ≤ 120 字节**（不是字符）。中文按 UTF-8 约每字 3 字节，所以**约 40 个汉字上限**。
- 手表按 `text_len` 截断，超长不会崩，但会被切掉。
- 建议 **20~30 字**，负一屏一行显示约 12 个汉字，两行半是舒适区。
- 不要放换行符（手表会当普通字符，显示成方块）。

### 2.5 示例（Kotlin）

```kotlin
fun buildDailyBrief(
    steps: Int,
    activeMin: Int,
    falls: Int,
    weather: Int,
    tempC: Int,
    text: String
): ByteArray {
    val body = text.toByteArray(Charsets.UTF_8).let {
        if (it.size > 120) it.copyOf(120) else it
    }

    return ByteBuffer.allocate(12 + body.size)
        .order(ByteOrder.LITTLE_ENDIAN)
        .put(0x01)                       // version
        .put(0x06)                       // cmd: DAILY_BRIEF
        .putInt(steps)
        .putShort(activeMin.toShort())
        .put(falls.toByte())
        .put(weather.toByte())
        .put(tempC.toByte())
        .put(body.size.toByte())
        .put(body)
        .array()
}
```

**注意 `ByteOrder.LITTLE_ENDIAN`**——手表按小端解析，用大端会把步数读成天文数字。

## 三、手机端要做的三件事

### 3.1 取天气

任选一个免费天气 API（和风、OpenWeather、或系统自带的 WeatherKit）。
只需要三个值：**天气码、温度、城市名（可选，手表不显示城市）**。

映射到 2.3 的表。**拿不到就发 0**，手表会隐藏天气行，不影响其他内容。

### 3.2 生成评语

把当天数据喂给已有的 LLM 通道（和 `AI_TEXT` 用的是同一个），
prompt 建议：

> 你是手表助理。用一句中文（不超过 25 字）点评今天的活动情况，
> 语气自然，不要感叹号堆砌，不要编造没有的数据。
> 数据：步数 {steps}，活动 {activeMin} 分钟，疑似跌倒 {falls} 次。

**跌倒次数 > 0 时，评语里要提到**——这是这个产品最重要的信息，
不要只夸步数。

### 3.3 什么时候发

三种时机，按优先级：

1. **手表打开负一屏时**（推荐）：
   手表侧目前没有"我要简报"的上行请求，所以这一条要等固件加一个触发。
   **当前实现没有这条，先不做。**
2. **每天固定时间**：建议 **21:00**（和固件的 `DAILY_BRIEF_HOUR` 对齐）。
   App 用 `WorkManager` 定时，即使 App 没在前台也发。
3. **手表每天第一次连上时**：检查当天是否已发过，没发就补一份。

**建议 2 + 3 一起做**：21:00 准时发，如果那时手表没连上，
下次连上补发。

### 3.4 数据从哪来

**步数、活动分钟、跌倒次数手表自己会算**，手机端理论上有两个选择：

- **A. 用手机自己的健康数据**（Health Connect）——如果用户允许
- **B. 用手机收到的手表上报**（`DataUpload` 的 STEPS / ACTIVITY / FALL_EVENT）

**建议 A**，因为手机通常有更完整的一天数据（用户不戴表时也算）。
但如果 A 拿不到，用 B 的最后已知值 + 本地累加。

**无论用哪边，都只是喂给 LLM 生成评语用**——手表负一屏显示的永远是
它自己的实时数字，手机上来的数字只影响那句话说什么。

## 四、兼容性

- **旧固件（< 本版本）收到 0x06 会打印 `unknown command 0x06` 并忽略**，
  不会崩。所以手机端可以先发，不影响老版本手表。
- **手表没连手机时**，负一屏显示本地统计 + “连接手机后可生成 AI 点评”，
  功能不残缺。
- **天气拿不到**时发 0，手表隐藏天气行。

## 五、验收标准

1. 手机发一帧 0x06，手表串口打印
   `BLE: daily_brief N steps, M min, F falls, w=W TC "评语"`。
2. 手表左滑进负一屏，能看到步数/活动/跌倒三个数字，
   右上角有天气和温度，底部有那句评语。
3. 断掉手机，左滑进负一屏，数字仍在（本地算的），
   天气隐藏，底部变成“连接手机后可生成 AI 点评”。
4. 评语发 200 字节（超长），手表不崩，只显示前 120 字节。
5. 发一个 `weather = 99`（非法码），手表隐藏天气行，不崩。

## 六、联调建议

先用 `nRF Connect` 或 `gatttool` 手动写一帧，确认固件侧解析正常，再接 App。
手工帧（hex，步数 4321、活动 37 分钟、跌倒 0、晴、23℃、评语“今天走得不错”）：

```
01 06 E1 10 00 00 25 00 00 01 17 12
E4 BB 8A E5 A4 A9 E8 B5 B0 E5 BE 97 E4 B8 8D E9 94 99
```

（`E1 10 00 00` = 4321 LE，`25 00` = 37 LE，`17` = 23℃，`12` = 18 字节评语，
后面 18 字节是“今天走得不错”的 UTF-8。）
